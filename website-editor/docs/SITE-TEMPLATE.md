# Site template

## What counts as a site

**A folder is a site when pages can be served from it** - `.html` directly in
it, or in a pages folder: `templates/`, `views/`, `pages/`, `public/`, `www/`.
Either way **that folder is the site**, the way a web server has a *document
root*: `/static/styles.css` means the root, so a Flask project
(`app.py` + `templates/` + `static/`) is **one** site rooted where `app.py`
is, and `templates/` is not a site of its own.

Which page opens first is a server's *index file list* - `index.html`,
`index.htm`, `default.html`, `home.html` - and a folder with pages but no
index still opens, at its first page by name.

It does not have to be the folder you opened in VS Code: Draw2Code scans a few
levels deep, lists every site it finds, and always offers *Choose another
folder...*. Whatever the layout, the development copy holds **every file in
the site folder**, so nothing is lost.

The layout below is how Draw2Code *organizes what it generates*, and what it
assumes when it writes files. Your own site does not have to match it.

```
my-site/
├── index.html        the entry page (this is how the site is recognized)
├── pages/            more pages: pages/about.html, pages/contact.html
├── css/              stylesheets, e.g. css/style.css
├── js/               scripts
└── assets/           images, fonts, downloads

my-site-dev/          the DEVELOPMENT COPY, made by the extension
└── .draw2code/         its own state (overrides, the fingerprint), ignored by git
    └── project.d2c   the import's label: open it to open the site
```

Nothing here is required - this is only what Draw2Code writes when it generates
(`index.html` + `css/style.css`), and a suggested place for your own files.

Every `.html` file in the site shows up in the preview's page dropdown,
wherever it lives. `.git`, `node_modules`, `__pycache__`, `venv`, `.venv`
and `.draw2code` are never copied.
A `-dev` folder is never listed as a site of its own.

**Opening a site.** Every site Draw2Code edits has a label, `project.d2c`, and
opening the label opens the site in the Designer - double-click it, or use
Open Editor. An import's label lives in its development copy
(`my-site-dev/.draw2code/project.d2c`, marked as an import and pointing back at
`my-site`), so your own folder is still not written to. The tab is named after
the folder the label is in, and only one site is open in the Designer at a time.

## A project you made (New Design, then Save)

**New Design** opens an untitled design, `Untitled-1.d2c`, which is nothing on
disk until you save it - an unsaved file like any other. **Ctrl+S** (or Save
Design, or File > Save) opens VS Code's Save dialog, starting in the open folder:

- the **name you type is the project's name**: saving `MyProject` in a folder
  makes the project in a new folder `MyProject` inside it, next to whatever
  is there (an empty folder of that name is used)
- a name that is already there is refused, saying so, and the design stays open

```
MyProject/
├── MyProject-dev/     the site: every page, and css/style.css shared by all
├── MyProject-prod/    the clean copy - made by Publish, not by saving
└── .draw2code/
    └── project.d2c    the project's label (its name, its folders, when it was
                       made, its page width, and the drawing as it was when
                       you saved it)
```

**Page width.** Every page is a column the project's page width wide (1440px
unless changed with Draw2Code: Page Width...), centred in the window. The
label remembers the width, and the `.page` rule of `css/style.css` gives it to
every page, so changing it rewrites only that one line.

**Publish** builds `MyProject-prod`: the site as it could be hosted, with
nothing of Draw2Code left in it - no `data-d2c` markers, no `draw2code/` stylesheets,
no "generated by" notes. The rules Draw2Code wrote for each page move into
`css/style.css`, scoped to that page, so it looks exactly like `-dev`. It is
rebuilt from scratch every time, so do not edit it by hand. It holds only the
site: Draw2Code's `.draw2code/` folder is not copied into it.

**Saving turns the design into a site.** The project opens in its own tab,
named `MyProject`, on the page you were looking at, and from then on it is
edited like any site (see "Saving edits" below). Open Editor lists the project
once, by its own name.

Until it is saved, the design is looked after by VS Code, like an unsaved file:
the tab shows ●, Ctrl+Z / Ctrl+Y and Edit > Undo step through the drawing
(undoing back to blank clears the ●), closing asks "Save changes?", and
closing VS Code keeps it - it is back, still unsaved, next time. Only one
design or site is open in the Designer at a time: opening another closes it,
asking first if it has unsaved work.

## Saving edits

An open site is saved like a file. An edit - a move, a colour, a new element,
a retitle, a page added with `+` - is held in the editor, and the tab shows
**●** until you save. Nothing reaches `-dev` before that.

- **Ctrl+S** (or File > Save) writes every held edit into `-dev`.
- **Closing** a tab with unsaved edits asks VS Code's own "Save changes?".
- **File > Revert File** throws the unsaved edits away.
- The **site preview** shows the unsaved edits too, so it always matches the editor.
- **Publish** takes the saved copy, so with unsaved edits it offers
  "Save and Publish" first.
- Closing VS Code with unsaved edits keeps them (VS Code's hot exit): they
  are back, still unsaved, when the site opens again.
- A page **changed on disk** (edited by hand, or synced in from your folder)
  shows at once if it has no unsaved edits. If it has, Draw2Code asks: **Keep
  mine** keeps your edits; **Load from disk** takes the file as it is now for
  that page only - other pages keep their edits, and with nothing left
  unsaved the ● goes. **Reset Working Copy** throws away unsaved edits along
  with the copy.
- The site opens where you left it: the page tabs that were open and the page
  shown are kept in its `project.d2c` (under `editor`). Switching pages is not
  an edit, so it never shows ●; where you are is written when you save, and
  when you close the site with nothing unsaved. Unsaved edits you drop with
  Don't Save leave it as the last save wrote it.

## Two copies: yours and the development one

**Your folder is your final copy, and Draw2Code does not write to it.** Not one
file, not even a hidden one. The first time a site is opened, the whole folder
is copied beside itself:

```
homepage/        yours. Untouched.
homepage-dev/    where every edit goes, when you save.
```

From then on:

- the **editor** and the **site preview** show `homepage-dev` (switch to
  *Original* in the preview to compare)
- the preview renders the page as a plain browser would: VS Code's own webview
  styles are reset, and relative links, images, stylesheets and scripts all
  resolve
- **Generate HTML** writes `index.html` and `css/style.css` into the
  development copy. If that page was not made by Draw2Code (an imported site),
  it asks first, because the canvas cannot read an existing page back yet
- edit anything in `homepage-dev/` by hand; the page refreshes on save
- **Edit** in the preview lets you select, nudge, resize, retype and delete
  parts of the real page. Moves are written as `position: relative` offsets,
  so an element keeps its place in the layout and the rest of the page does
  not reflow.
  Each page's changes go to its own stylesheet (`draw2code/<page>.css`), linked
  last in that page's `<head>`. **Revert element** and **Revert page** undo them.
- clicking **inside** a selected element selects the thing you clicked; press
  on the selected element itself to move it. An element placed at exact
  coordinates is moved to its new place; one in the page's flow is nudged.
- a **template** (Jinja's `{% for %}` / `{{ name }}`) is shown as it is, and
  edited as it is - you are editing the template, not the page a server would
  build from it.
- **drawing on a real page**: the canvas's tools sit above the bar (Rect,
  Ellipse, Line, Pen, Button, Input, Label), and three only the editor has:
  Text (a `<p>`), Heading (an `<h1>`) and Image (an `<img>`). Drag to draw - or click, for a
  widget at its default size - and Draw2Code asks where it goes, every time:
  **Place freely** puts it exactly where you drew it and moves nothing
  (`position: absolute`, in the page's own coordinates - on a page made in
  Draw2Code, inside its `.page` wrapper like everything generated); **Add to
  `main.container`** makes it the last child of the section you drew over,
  and the page flows around it. The element is the canvas's element - same
  model, same generator, same markup - written into the development copy
  with an id nobody in the page has (`rect-1`, `button-2`). Esc on the
  question adds nothing. Like the canvas, a tool is used once and Select
  comes back.
- **pictures**: Image asks for the file (only .png, .jpg, .jpeg, .gif, .webp
  and .svg, checked again after the dialog) and then for its alt text - what
  it shows, for people who cannot see it; leave it empty for decoration. Esc
  at either adds nothing. A file from outside the development copy is copied
  into its `assets/` folder (`logo.png` becomes `logo-2.png` when the name is
  taken); one already inside the copy is used where it is. The `src` is
  written relative to the page (`../assets/logo.png` from `pages/a.html`) and
  must stay inside the site: no scheme, no absolute path, no `..` out of it.
  The picture fits inside its box (`object-fit: contain`). A file copied this
  session follows its image: delete the image (or undo adding it, or Don't
  Save) and the file is deleted; undo brings both back. Files that were in the
  site before are never deleted. Publish copies `assets/` like any other file.
- **colours and borders**: the toolbar has the canvas's controls - Fill,
  None, Border colour and width, Text. With an element selected they show
  what it has now; a change shows at once and is written when the picker
  closes, so a colour is one undo step. Fill is the element's background,
  border colour + width become one `border`, Text is its `color`. A drawing
  Draw2Code added (an inline `<svg>`) is one thing: clicking its shape selects
  the svg, and its colours are written for the shape inside it
  (`#rect-1 > * { fill: ... }`). With nothing selected the controls set the
  next shape drawn, as on the canvas; widgets keep their own look.
  **px** is the selected element's font size (6 to 96px): it shows at once
  and is written when you leave the box (Enter, or a click elsewhere), so
  however many arrow clicks it took, it is one undo step. Esc, or an empty
  box, puts back the size it had and writes nothing; the element stays
  selected.
- **bold and alignment**: **B** and the left / centre / right buttons show
  what the selected element has now and change it with one click, one undo
  step each. B writes `font-weight: bold`, or `normal` on text that is bold
  already (a heading). Alignment writes `text-align`; on a flex box (a label,
  a button made a link) it also writes `justify-content`, which is what
  moves a single line there. A drawing or a picture has no words, so for
  those, and with nothing selected, the buttons are off; alignment is off
  on an inline element too (a link inside a sentence), which is only as
  wide as its words. A button aligned left or right and then made a link
  keeps its words where they were.
- **text that wraps**: Text and Heading wrap inside their box and keep their
  line breaks (`white-space: pre-wrap`); the drawn height is the least they
  take (`min-height`, and a resize by a top or bottom handle sets it too), so
  more text makes them taller instead of being cut off. While retyping,
  **Shift+Enter** starts a new line and Enter still keeps the text; the new
  line is a real newline in the page, not a `<br>`. Only text that shows line
  breaks gets one (anything with `pre`, `pre-wrap`, `pre-line` or
  `break-spaces`); in a label or a button Shift+Enter keeps the text like
  Enter.
- **renaming a page**: double-click the text of any tab - showing or not -
  and type. Enter keeps it, Esc does not, and a blank title is refused. In the
  editor it rewrites that page's `<title>` in the development copy (only the
  text between the tags); on the canvas it is the page's title in the design.
  A single click on a tab still shows its page - after a quarter of a second,
  so a double-click can say "rename" first. A new page from `+` takes the
  **home page's** title, since pages of one site usually share its name.
- **Ctrl+Z / Ctrl+Y** (Ctrl+Shift+Z too) undo and redo every edit the same
  way - a nudge, a resize, a retype, an added or removed element, a revert -
  because each step is the whole page as it was (the file and its rules), not
  a description of the edit. The history is the site's, shared by the editor
  and the preview; undoing an edit made on another page takes you to that
  page. Adding a page with + is a step too: undoing it takes the page away.
  When other pages still link to a page that goes (that undo, or its file
  deleted on disk), one warning names them; their links are left as they are.
  In an open site these are VS Code's own undo steps - Edit > Undo works, and
  undoing back to where you last saved clears the ●. While retyping, Ctrl+Z is
  the text field's own. A click that never moved is not an edit and leaves no step. The canvas has the same keys over
  its design: drawing, moving, deleting, adding or closing pages, renaming.
  Switching pages is not an edit, so it is never a step.
- while editing, a link is an element first: the first click **selects** it,
  a double-click **retypes** it, and clicking a link that is already selected
  **follows** it. (Following on the first click made a link styled as a button
  impossible to edit - the page was gone before the double-click landed.)
- **Delete** or Backspace removes the selected element - its markup, and the
  rules Draw2Code wrote for it and for what was inside it (`#button-1`,
  `#button-1:hover`, `#button-1::placeholder`, `#button-1 > *`; `#button-10`
  is another element and keeps its own). A selected link is removed, not
  followed, and a selected text box is removed, not typed in. `<html>`,
  `<head>` and `<body>` are the page itself and are never removed. While
  retyping, or in the address bar, the keys edit text as usual; Backspace
  never goes back a page. Ctrl+Z brings the element back.
- **Publish** is the one thing that writes to your folder. It lists every
  added and changed file and asks before copying them across.

The copy is a real folder, so you can open its files, run it, and keep it in
git. Only `homepage-dev/.draw2code/` is ignored (it holds Draw2Code's own state).

A `-dev` folder is never treated as a site of its own: it is not listed when
Draw2Code asks which folder is the site, and choosing one anyway (by browsing to
it) opens the site beside it, so you never end up editing `homepage-dev-dev`.
A copy you made by hand is adopted as it is - Draw2Code writes down what your
folder looks like now, and only later changes to it are synced.

## Editing your own files while Draw2Code is open

If you change `homepage/` by hand, that change is copied into `homepage-dev/`
straight away - no question asked, because the copy is the only thing being
edited and nothing would be lost.

The exception is a file changed in **both** places. Then Draw2Code asks once:

> **1 file changed in both homepage and homepage-dev.** · *Keep homepage-dev* · *Take homepage*

Whichever you pick, that change is written down as seen, so you are not asked
about it twice. This is measured against a fingerprint of your folder taken
when it was copied (`homepage-dev/.draw2code/source.json`) - not by comparing
the two folders, which would call your own edits a change forever.

## Importing a site

Paste a website folder into the open folder, or open a folder that already
has one, and Draw2Code says so:

> **Detected import of trivia.** Draw it in the editor?  ·  *Redraw* · *Keep current contents*

- **Redraw** makes the development copy and shows that site's page in the editor.
  If the canvas has a drawing on it, it says how much will be discarded first.
- **Keep current contents** does nothing and stops asking about that folder.
  *Draw2Code Web Editor: Draw a Site in the Editor* brings it back.
- Several sites at once are listed, and you pick one.
- If the original changes after it was copied, those changes are synced into
  the development copy for you (see above).

## Commands

| Command | Does |
| --- | --- |
| Open Editor | Asks which folder is the site, then shows that site's page in the editor: the real page, with selection outlines and handles, under the same browser bar the canvas draws. The tab shows the page's title, the address bar is typed into (a page of the site, with or without `.html`; the list drops down as you type), links in the page work, and back/forward walk your history. Everything you do lands in `<site>-dev` |
| New Design | Turns the editor back into the blank canvas for a new design (and offers back a design you did not save) |
| Save Design | Ctrl+S in the tab. Saves a new design as a project and switches to editing it |
| Draw a Site in the Editor | Pick a site and show it in the editor (also un-silences a folder you kept quiet) |
| Open Site Preview | The preview alone (same asking and same development copy) |
| Publish (update the final copy) | The only thing that writes to your own folder. Lists added and changed files, asks, then copies them from `<site>-dev`. Files that exist only in your folder are never deleted |
| Reset Working Copy | Throws `<site>-dev` away, copies your folder again, and forgets every edit recorded for it |
